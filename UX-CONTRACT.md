# UX Contract

## Product context

- Audience: desktop Markdown authors.
- Primary jobs: create, open, edit, save, organize, and export local Markdown documents.
- Target markets: global desktop users.
- Active locales: simplified Chinese and English.
- Accessibility target: WCAG 2.2 AA where webview and platform APIs permit.

## Navigation and responsive behavior

- Document title reflects the active file path.
- The editor is the focus destination after opening, cancelling, or completing an editing action.
- Sidebar selection must not replace an unsaved document without the canonical transition guard.
- Rendered, Source and Split preview are selected in Preferences > Editor > Editor mode. The editing surface does not show a mode-switch strip; its existing source and preview labels remain visible.

## Overlays and feedback

- Dialog primitive: Tauri dialog plugin. Theme uninstall names the target and explains the active-theme fallback; Cancel preserves the installed theme.
- Image settings retain their unsaved draft across settings tabs. Closing uses the existing single preferences close handler: image Save/Discard/dismiss is resolved before any shortcut confirmation, and failed saves retain the draft and reveal the image tab. Dismissing either confirmation keeps the window and pending inputs; pending settings operations prevent closure.
- Preferences navigation uses keyboard-focusable buttons. Markdown toggles/selects expose labels and hints. Theme selection exposes the current theme through text and `aria-pressed`; protected entries have no uninstall action. Status areas reserve space, and theme previews wrap within the settings scroll surface.
- Unsaved changes: Save is the safe path; Discard is explicit. Cancelling the Save As picker cancels the pending transition.
- Save failure: retain dirty state, preserve editor contents, log the error, and show a localized error dialog.

## Async and resilience

- Document windows remember client width and height in logical pixels in one SQLite record. Startup and new document windows restore while hidden, fitting the destination monitor's work area including native frame size. Minimized and invalid dimensions do not overwrite the cached valid size; preference/about windows do not contribute. Approved close awaits dimension persistence and revalidates before destroying the window. Quit/update persist after all participants prepare and before final validation, so preference I/O cannot weaken document protection; failed preference writes are logged and do not block a safe close. The latest actually destroyed document window becomes the default for reopening.
- Sidebar visibility is restored from a strictly validated local preference and saved for all show/hide entry points. The existing preferred-width preference remains authoritative; responsive clamping does not replace it. Storage failures retain the live interface and allow subsequent retry by interacting again.

- Editor mode is a strictly validated local preference, separate from each document window's current view. Successful persistence broadcasts through native events, with storage events as the browser/fallback path; receivers apply without rebroadcasting. Startup waits for the document editor to be ready. Each window retains only the latest pending preference request while saving, exporting, loading, navigating segments, handling resources or lifecycle approval, or composing input. When ready it uses the existing guarded mode switch; rendering failure retains source/history and offers explicit retry. Storage failure retains the previous preference, and saved-but-sync-failed feedback distinguishes persistence from delivery. Search source positioning and rendered outline navigation may change the current view without rewriting the saved preference. Applying a queued request does not replace document content or mark it dirty merely for changing views.

- The editor shares one canonical whole-document Markdown value across source editing, save, drafts, search and export. Fresh source preserves exact Markdown and line endings until rendered edits change it. Unmodified mode round trips retain rendered state/history; actual source changes rebuild the rendered editor and reset only its undo history. Source undo survives mode changes. Mode switches are blocked during save, export, document transitions and IME composition; render failures retain source and offer retry.
- Source and split preview use one bounded history and UTF16 selections. Whole-document replacements form one undo transaction and reject operations that cannot retain that transaction. Save As attachment rewriting rebases source selection and both history branches. Preview is debounced, discards stale renders, sanitizes HTML, resolves document images and identifies the displayed line window for large documents. Input composition defers save, drafts and lifecycle approval until completion.
- Whole-document search matches literal Markdown across every segment, yields between bounded scans and opens exact results in source mode. Stale document generations invalidate navigation/replacement. Replacement requires a preview and explicit confirmation; all replacements scan up to 10,000 matches rather than replacing only the displayed 300 results. Workspace search recursively reads `.md`/`.markdown` files, reports progress and skips links, unreadable and oversized files. Sessions belong to the requesting window, support cancellation and expire after 120 seconds. Limits are 2,000 files, 20,000 directory entries, 4 MiB per file, 64 MiB read, depth 32 and 300 results. Opening a workspace result uses the common unsaved guard, then checks canonical identity and file version before positioning. Workspace replacement is unavailable.
- Conflict comparison reads the complete current Markdown and latest disk snapshot without changing the editor, save baseline or conflict state. Revision, path and disk changes mark the comparison stale. Refresh retries the read; closing or Escape cancels late results and restores editing focus. Line, work and display budgets show explicit partial counts and omitted ranges instead of claiming complete comparison. Text is escaped and additions/removals have symbols as well as color.

- Shortcut definitions, normalization, event matching and conflict validation share one utility. Shortcut drafts survive settings-tab navigation; complete drafts support swapping assignments before saving. SQLite persists desktop preferences, with localStorage for browser previews and cross-window fallback. Startup and native events apply live bindings; stale reads cannot replace newer updates. Saving does not dispatch document transactions or change selection/history. Recording fields, ordinary inputs and IME composition retain their own keyboard behavior. Owned editor shortcuts dispatch once; cleared or remapped defaults are suppressed before Tiptap keymaps. Clipboard defaults retain the native paste pipeline.
- Editor fonts are validated and remembered with the existing local editor preferences. Startup, native cross-window events, and storage events apply only document CSS variables; application chrome and code font families stay consistent. Custom names identify one installed font and fall back to the system stack. A local save failure retains the current font, while a broadcast failure after persistence is reported as a synchronization failure. Changing typography does not dispatch editor transactions or alter document selection/history. Static image exports inherit the selected document typography.
- Markdown settings are loaded once with retry, saved pessimistically to SQLite, then applied in place and broadcast. Future parsing/output and clipboard behavior read live settings; changed parsing options reindex non-current large-file headings while keeping the current document intact; current content, selection and undo history remain. A broadcast failure after persistence is reported as synchronization failure, never as a failed save.
- Edit-menu and context-menu Paste share the native editor paste pipeline. Pure text obeys the Markdown conversion switch; rich HTML retains its supplied format. If browser clipboard access fails, Tauri text access is used. Empty clipboards are silent, errors retain content/selection with a localized dialog, and a delayed read cannot insert into a document changed during the read.\n- Theme lists are reactive and shared by startup, refresh, and cross-window events. A newer catalog prevents an older read from overwriting it. Install/uninstall applies the completed mutation before refreshing; a refresh failure offers retry without misreporting the mutation as failed. Deleted current themes revert to Light/Dark of the same type in every window.
- Image export snapshots the entire Markdown document, including edited and untouched large-file segments, and renders once into a temporary static surface. Export options are validated and remembered locally after success. The editor content, selection, history, scroll and native window resizability remain untouched. One export may be pending at a time; PNG transparency is unavailable for JPEG. Dimensions are checked before allocating the canvas; oversized or unavailable image resources produce recoverable errors. The selected extension, MIME and encoded bytes must agree, and native save-path confirmation is preserved.
- File saves are pessimistic and serialized; only the revision actually written may become saved.
- Every opened document receives a native content hash and canonical file identity. Cross-window save events, visible-window polling and focus checks detect disk changes. Conditional saves check the expected content before staging and immediately before replacement under a canonical-path lock; a conflict retains edits/drafts and pauses auto-save. Reload/overwrite confirmations name the file, and overwrite uses the last observed disk version rather than bypassing conflict detection. Open failures restore content, editor state/history, file baseline and draft protection.
- Save As stages unique local-image copies, rewrites only parsed Markdown/HTML image references using UTF8 source spans, then conditionally saves the target. Failed saves remove only newly copied assets; originals and unrelated files stay intact. Alias mapping updates serialized Markdown and live image resolution without dispatching editor transactions, so existing undo and cached segment state remain usable. Unnamed images use durable local draft assets; transient caches are cleaned on upload success or failure. PicGo checks HTTP status, success payload, a valid HTTP(S) URL and a 30-second timeout; CLI failure/empty output never inserts an empty image.
- A successful file write does not approve navigation while newer edits remain dirty. Save As always retains its own destination request. Save, Discard and Cancel are distinct localized actions; picker cancellation and failed draft cleanup prevent navigation.
- Quit and update installation coordinate all document windows by addressed preparation and validation events. Participants pause editing and auto-save, wait for active saves, and reject pending exports, resource tasks, document loading and segment navigation. Window identities and revisions are checked again before the action. Cancellation, timeout or failed delivery releases the temporary lock and restores dirty-document recovery snapshots; success avoids recreating deliberately discarded drafts. Updates download before protection and install only after approval.
- Local recovery snapshots are debounced independently of auto-save and include unnamed documents and all large-file segments. Drafts are scoped by unique IDs and active owner leases, remain on this computer until explicit save/discard, and support 128 MiB of Markdown per document. Native storage syncs a new immutable snapshot before pruning its predecessor; an interrupted write retains the last valid snapshot. Browser previews use scoped localStorage records. Active windows' drafts are excluded from recovery, and claim checks prevent duplicate restoration. No recovery silently overwrites an original file: restore opens an unnamed dirty copy, using the original path only to resolve existing relative resources. Failed restoration rolls back the live document and retains the recovery record. Storage and cleanup errors remain visible with retry.
- HTML, PDF, Word and image exports snapshot the complete Markdown document before the picker. HTML/PDF share static preparation with image export, embed images and Mermaid output, carry document typography/theme styles, and use portable native MathML. Exports preserve the live document, selection and segment position; one export may run at a time from picker through confirmed write. New or dirty documents may export directly. PDF prints all pages, uses a dynamically allocated browser port, and writes via the same staged replacement helper as HTML/image/Word.
- Files at or above 512 KiB are split at safe Markdown block boundaries. Only the current segment enters the WYSIWYG document; untouched segments retain their original Markdown and are joined during save.
- Segment boundaries respect complete top-level lists, quotes, code, HTML containers and block math. All segments receive document-wide reference definitions during rendering without adding them to untouched source; definitions without editor nodes survive edits to their own segment. Code fences serialize with a safe delimiter length. Search replaces the selected result, clearing removes stored results, and all replacements share one undo transaction; its current-segment scope remains visible, with IME-safe navigation and labeled controls.
- The outline indexes headings in every segment without loading the full document into WYSIWYG. Edits refresh the current segment index. Filtering searches folded descendants; clearing restores disclosure states. The filter is transient per sidebar session. Search stays fixed while the remaining outline panel owns its scrollbar.
- Segment navigation retains independent ProseMirror states, selection and scroll for up to eight recent segments within an approximate 16 MiB content/history budget. Eviction retains Markdown and numeric bookmarks while releasing old undo history. New documents clear the cache; parsing changes invalidate non-current states. Statistics index other segments asynchronously and show whole-document word and character quantities in the titlebar without a range badge or selector. Source and Split preview count the complete Markdown buffer. Outline and code highlighting reuse unaffected blocks; selection-only/prose changes do not trigger full code scans. Long code exceeding highlighting limits falls back to plain text.
- Segment navigation defaults to Previous/Next buttons. The alternate setting switches on a downward scroll at the bottom or an upward scroll at the top. It responds to wheel, touch, Page Up/Down, and scrollbar input, not programmatic editor scrolling; it is saved across windows. First visits enter the next segment at its top and previous segment at its bottom; revisits restore their recorded selection/scroll. Heading jumps explicitly override that restoration.
- Auto-save waits 600ms after the latest edit and shares the manual-save queue.
- Duplicate saves wait for the active save instead of racing it.
- Failed and cancelled saves never permit a guarded document transition.
- Rust writes stage and sync complete content before replacing the target, retaining a backup during replacement.

## Validation

- Tauri command responses are checked for both transport failure and non-zero response codes.
- Malformed image data/configuration returns an error instead of panicking.
- File picker cancellation is a normal, non-error state.
- Theme files are UTF-8 JSON up to 1 MiB, with all schema fields and 14 valid hex colors. Theme IDs use 1–128 ASCII letters/digits/hyphens/underscores, are unique ignoring case, and reserve Light/Dark. Installed files live under the application data directory; uninstall validates the directory, identity and canonical path, rejects links/reparse points, and cannot remove bundled resources.
